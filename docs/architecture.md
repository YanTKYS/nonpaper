# アーキテクチャ

全端末へEXEを配布・更新する運用負担を避け、現行ブラウザーだけで庁内の複数OSから利用できるブラウザー型を採用した。HTML/CSS/JavaScriptは表示と操作、Minimal APIは検証・認可・HTTP配信、`EventService`はユースケースとトークン、`IEventRepository`は永続化を担当する。

小規模な初期版ではイベント単位のJSONでバックアップと障害調査を容易にする。書込みはイベント別ロック、一時ファイル、置換で保護する。検索、利用者管理、複数サーバーが必要になれば `IEventRepository` の実装をSQLite等に交換し、画面/APIを維持できる。

PDFとJSONは `wwwroot` の外に置く。静的配信に載せると公開状態の判定を経ずに資料が読めるため、PDFは公開状態とイベントへの所属をAPIで確認して初めて配信する。IDは形式を限定し、外部から渡されたファイル名は表示と記録にだけ使うことで、利用者入力から任意のパスを組み立てない。
